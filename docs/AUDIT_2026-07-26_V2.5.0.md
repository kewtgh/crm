# Lumina Education CRM v2.5.0 完整审计

- 审计日期：2026-07-26
- 审计基线：`ae49322 feat: release v2.4.0 reliability audit`
- 范围：安全、运行时配置、架构、数据库与业务不变量、发布工程、UI/UX、可访问性和产品能力
- 审计方式：源码反查、生产构建、Node 契约、schema lint、pgTAP、业务/HTTP/鉴权 smoke、固定 Chromium 1228 分阶段验证和人工截图复核

## 结论

v2.4.0 没有发现 P0、直接权限提升、数据丢失或发布阻断。现有员工身份、AAL2、同源校验、RLS、
安全导出、审批、队列与可复验发布门基础完整。本轮确认 2 个上线前 P1、5 个 P2 和 4 个 P3
问题；自动化全绿并不代表没有人工可见缺陷，运营中心动态翻译键就是本轮的直接例证。

## 已确认问题

### P1：会话刷新 returnTo 可被反斜杠绕过

`app/api/auth/refresh/route.ts` 只拒绝以 `//` 开头的目标。`%2F%5Cevil.example` 解码后为
`/\evil.example`，仍通过检查，而 WHATWG URL 会将其解析为站外地址。影响是认证刷新后的开放跳转，
可用于可信域跳转钓鱼。修复必须在解析后比较 origin，并覆盖反斜杠、控制字符和编码变体。

### P1：生产环境预检接受占位值和错误类型

`lib/runtime-environment.ts` 对 Turnstile site key、Supabase keys 仅验证非空，Worker URL、token
和批次大小也只判断存在。使用 `.env.example` 风格占位值执行现有 schema，得到
`{"valid":true,"configured":10,"expected":10,"missing":[]}`。这可能让登录不可用或 Worker
错误配置延迟到运行时才暴露。

### P2：请求内身份水合缺少显式去重

CRM 根布局执行完整用户水合，大量页面和管理员布局又调用 `requireCapability` / `requireRole`。
身份读取包含 Auth user、profile 和 membership 三个上游请求，且使用 `cache: no-store`。代码没有
请求级 memoization，不能把是否去重押在 Vinext/React 的隐式行为上。

### P2：运营中心缺少动态枚举翻译

数据库返回 `APPROVALS`、`IMPORTS` 等队列键；组件动态调用
`t(\`operations.key.${queue.key}\`)`，但中英文目录未覆盖全部枚举。真实中文页面直接显示
`operations.key.APPROVALS` 和 `operations.key.IMPORTS`。

### P2：自动 CI 与完整发布门不一致

GitHub CI 只跑类型、Lint、构建/Node 契约和依赖审计。数据库、业务 smoke、真实设备鉴权和
固定浏览器只存在于手工发布门，PR 合并前不能自动阻止 RLS、迁移或关键业务回归。

### P2：移动运营中心信息架构过载

375px 页面把发布健康、业务指标、九类队列、Worker、失败恢复、六个连接器、规则建议和权限
解释器全部纵向堆叠。页面无溢出，但需要极长滚动，异常定位和单手操作效率较低。

### P2：审计事件过于底层

管理员首页直接展示 `INSERT` / `DELETE`、表名和 UUID 片段。数据真实但缺少业务语义，运营人员
难以快速回答“谁对哪个业务对象做了什么”。

### P3：空列表、移动导航和脚本默认值

- 财务多个空分区只显示 `0 条 / 第 1 页` 分页器，没有明确空状态。
- 设置页移动标签和顶部搜索空间紧张，当前标签缺少清晰滚动提示。
- `smoke-auth-device.cjs` 默认 `localhost:3210`，项目与发布门使用 3200；单独运行标准脚本失败。
- `v200-workspaces.tsx`、`app-shell.tsx`、`settings-page.tsx` 等大型客户端模块职责过多。

## v2.5.0 产品扩展建议

1. 供应商中立的可观测性：结构化 request ID、API 时延/错误、Worker/队列事件和可选外部接收器。
2. 企业身份：Supabase SSO/SAML 启动与回调、受保护的 SCIM 用户生命周期接口、显式启用和审计。
3. 角色化行动中心：把任务、审批、续约、隐私截止期和失败运营项合并为可筛选工作清单。
4. 连接器验证：在正式同步前执行有界 sandbox 验证，保存不可变验证凭证并显示最近结果。
5. 发布工程：PR 数据库门、独立全栈门禁和动态国际化/开放跳转回归。
