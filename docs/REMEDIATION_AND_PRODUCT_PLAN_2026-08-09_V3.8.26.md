# Lumina CRM v3.8.26 修复与产品计划

- 计划日期：2026-08-09
- 输入：`AUDIT_2026-08-09_V3.8.26.md`
- 目标：在不扩大认证、部署和数据边界的前提下，闭环员工目录 UI/UX、业务筛选、可访问性与版本一致性

## WP-1 员工目录响应式修复

1. 将固定六列目录在 680px 以下转换为语义清楚的单列卡片。
2. 为账号、角色、MFA、最近登录提供本地化移动端字段标签。
3. 保留 44px 操作触点、操作菜单浮层、长用户名/邮箱换行和分页可用性。
4. 增加源代码合同，防止固定网格再次成为移动端唯一布局。

验收：`/admin/users` 在 375px 无 document 横向溢出、无未命名控件、无低对比文本。

## WP-2 生命周期与角色筛选

1. 定义受控筛选值：生命周期 `ALL/ACTIVE/PENDING/SUSPENDED`，角色为 `ALL` 或现有 AppRole。
2. API 对筛选参数执行白名单验证；非法值返回 400，不把未知输入拼接到 SQL。
3. repository 在分页前组合 workspace、文本、生命周期和角色条件。
4. UI 增加双语筛选控件；改变筛选时回到第一页，并与搜索、分页和刷新并发安全地工作。
5. 修正搜索占位文案，使其只描述姓名、账号和邮箱；角色由明确筛选器承担。

验收：浏览器可组合筛选；合同测试锁定参数验证、SQL 参数化和分页前筛选。

## WP-3 操作菜单键盘闭环

1. 打开菜单后聚焦第一个可操作项。
2. 支持 ArrowUp、ArrowDown、Home、End 和 Escape。
3. Escape 关闭后恢复到对应触发按钮；点击外部关闭不劫持用户焦点。
4. 状态变更仍必须经过确认对话框；受保护账号与本人账号仍不可停用。

验收：现有状态确认合同继续通过，并增加菜单键盘合同/浏览器断言。

## WP-4 发布信息与防回归

1. 更新 `package.json`、`package-lock.json`、`lib/version.ts` 为 3.8.26。
2. 更新 README 当前发布摘要和 `docs/IMPLEMENTATION_STATUS.md`。
3. 扩展 release-version 合同，将 README 当前发布候选版本纳入同步检查。
4. 完成后新增最终复审文档，逐项核对本计划是否遗漏或未完成。

## WP-5 分层验证与交付

按一次一个类别执行：

1. 员工目录定向测试。
2. TypeScript 类型检查。
3. ESLint。
4. 应用合同测试。
5. 迁移清单验证和部署合同测试（确认未破坏发布版本合同）。
6. 源代码变化后执行一次生产构建。
7. 先复跑 Chromium `07-admin`；通过后继续此前未运行的 `08-interactions`、
   `09-keyboard`、`10-permissions`，最后合并同一构建证据。必要时再检查受影响阶段，不重复
   已通过且未受影响的阶段。
8. `git diff --check`、计划闭环复审、版本提交。

## WP-6 最终复审补充：嵌套关系基数

1. 修正数据库网关的唯一性元数据查询：只有有效、非部分、恰好一个键列的唯一索引才能
   把子表外键关系判定为一对一。
2. 复合唯一索引中的单个外键继续按一对多返回数组；不在业务 repository 中容忍错误形状。
3. 增加网关源码合同，并用家庭成员新增/读取/移除完整浏览器工作流验证真实数据库行为。
4. 复跑此前停止的 Chromium 阶段 09 和 10；其他阶段只有在源码/构建证据签名要求时才重跑。

验收：保存首个家庭成员后详情 API 返回 200 和数组，移除确认焦点闭环通过；其他嵌套关系
合同不退化。
