# Lumina CRM v3.8.26 项目与应用审计

- 审计日期：2026-08-09
- 审计基线：`f8cfe77`（v3.8.25，工作区干净）
- 目标版本：3.8.26 release candidate
- 范围：架构、业务逻辑、安全边界、数据访问、UI/UX、可访问性、测试、构建与运维合同

## 1. 结论摘要

当前应用不是原型或占位实现。认证、权限、数据库角色与 RLS、迁移、异步通信投递、
部署原子切换和主要 CRM 业务页面已有较完整的实现与合同测试。本轮没有发现需要推翻
现有总体架构的高危设计缺陷，也没有发现认证绕过、匿名对象读取或跨工作区访问证据。

本轮确认 4 个应在当前版本闭环的问题：

| 优先级 | 发现 | 影响 | 证据 |
| --- | --- | --- | --- |
| P1 | 员工账号目录在 375px 视口仍使用固定六列网格 | 页面宽度被撑到 911px，主要字段和操作离开可视区 | Chromium 1228 `07-admin` 的 `/admin/users` 检查失败；截图与 `report.json` 已保存在 Git 忽略的 QA 证据目录 |
| P1 | 员工目录只有文本搜索，没有生命周期和角色筛选 | 账号增长后难以定位待确认、已停用、管理员或具体销售角色；邀请补发与访问治理效率低 | `StaffUsersPage` 和 `/api/admin/users` 只传递 `query/page/pageSize` |
| P2 | 员工操作菜单声明为 ARIA menu，但打开、Escape 和方向键焦点闭环不完整 | 键盘用户打开菜单后缺少稳定的首项聚焦、方向键导航与触发器焦点恢复 | `staff-users-page.tsx` 只在 document 上关闭菜单，没有 menu roving focus |
| P2 | README 发布候选版本停在 3.8.19，而运行版本已是 3.8.25 | 运维人员读取错误发布信息；现有版本合同遗漏 README | `package.json`、锁文件和 `lib/version.ts` 为 3.8.25，README 首行仍为 3.8.19 |

最终计划复审的完整 Chromium 工作流又发现一项 P1 架构缺陷：数据库网关以“外键列出现
在任意唯一索引中”判断一对一关系，没有要求索引只有该列。`household_members` 的
`(household_id, contact_id)` 复合唯一约束因此把家庭到成员误判成一对一；空家庭正常，
保存第一个成员后详情 API 将对象当数组调用 `.map()`，返回 500。该问题纳入本版本闭环，
并扩展到网关通用判定修复，而不是在家庭页面做类型兜底。

## 2. 架构与业务审查

### 2.1 保留的设计

- Web、Worker、迁移、备份和系统查询使用分离的 PostgreSQL 身份；RLS 继续作为纵深防御。
- 认证使用应用自有账号、Argon2id、服务端不透明 Session、CSRF、TOTP、恢复码和可信设备。
- 通信邮件由可租约、可 fencing、带稳定幂等键的 Worker 负责；Web 只完成持久化排队。
- 对象下载只接受有时效签名 token，本地存储 route 不接受任意对象 key。
- 生产部署使用固定 rootless Docker/Compose 边界、前向迁移和应用镜像原子切换/回滚。
- 页面具备真实数据库加载、错误/空状态、分页、权限导航和双语元数据，没有 demo 数据回退。

### 2.2 可维护性观察

部分历史组件和仓储文件较长，CSS 也由多个版本工作包累计在单一文件中；这会提高后续修改
的认知成本，但本轮没有发现由此直接造成的运行错误。为避免把当前修复扩大为无收益重构，
本次只把员工目录行拆出局部可访问组件，并用有命名的 CSS 区块封装响应式规则。更大规模的
CSS 分层或 repository 拆分应在有独立性能/维护指标时另立任务，不作为本版本门禁。

## 4. 新功能建议与取舍

本轮采用“员工目录服务端筛选”作为可立即交付的新功能：增加全部、活跃、待确认、已停用
生命周期筛选，以及角色筛选；筛选发生在数据库分页之前，保证总数和页数正确，并与搜索
组合使用。

不引入泛化 AI、额外第三方平台、聊天机器人或新的同步集成。项目已有 AI 建议审核、自动化、
导入、导出、门户、数据治理和消息队列，在没有真实用户需求、供应商合同和数据处理评估前，
继续增加外部依赖会扩大隐私与运维边界，当前审计不建议这样做。

## 5. 外部与生产门禁

真实 VPS rootless daemon、Cloudflare Tunnel/Caddy、DNS/TLS、邮件供应商、对象存储生命周期、
生产备份恢复和灾难演练不能由本地仓库审计替代。它们继续按现有 runbook 执行，任何 rootful
Docker 连接、迁移校验失败、Worker readiness 失败或配对备份缺失都应阻断发布。
