# 客户运营与导航审计及实施计划 — v3.12.0

## 范围和现状

审计用户列出的六项，以及一级、二级入口的名称、分类和层级；不执行全库/十阶段发布回归，不部署、不推送。

1. 四级关系已有组织里程碑、覆盖目标、销售统计和静态行动手册；联系人有 communication_level。详情页与日常跟进割裂，缺少客户级目标、期限、跟进记录、可追踪的关键结果。
2. 任务、活动时间线、AI 规则建议和业绩目标均已存在，但不是统一客户运营工作台。新增轻量目标/关键结果闭环，不另造销售业绩会计系统。
3. 学校详情主要是混合时间线，联系人详情主要是档案/同意；没有学校简称。学生、家庭、门户分散。导航把学业升年放入数据、隐私请求放入个人账户、合同财务等全部塞进销售，分类不合理。
4. 下拉搜索空查询/单字查询被服务端拦截；所有类别并行查询，客户端再过滤。组件二次过滤会丢失服务端别名命中结果，回调变化也可能重复触发。
5. 日期原生图标和显式按钮重复；原生日历的月份/年份切换不可由应用控制。使用可控、键盘可用的轻量日期面板，不新增外部依赖；月份/年份选择后立即回到日期网格。
6. 创建客户可选其他 owner，但 INSERT RLS 要求 owner=actor。新增原子创建 RPC，仅管理员/销售总监可分配其他有效工作区用户。组织和职位对家庭个人客户不应必填。尚无请求 364d7836-eb8a-4721-9be4-3104566196d4 的日志，不能断言具体现场原因；验证已确认的代码路径并改善错误信息。
7. 独立 Cloudflare Email Worker 已实现 Resend，CRM 具有发信队列、重试、幂等和同意校验。未实现企业邮箱收件/OAuth 授权，账户凭据未提供。模板自动替换和企业邮箱 SMTP 中继适配可先落地；真实账号授权、SMTP 服务和双向同步明确属于部署配置/后续能力，不能伪称已接通。

## 一级、二级入口审计与结果

| 原分类/入口 | 修正与保留原因 |
| --- | --- |
| 总览：仪表盘、行动中心、日程 | 保留；日程内日历/任务为不同时间管理视图 |
| 关系：学校、联系人、学生、家庭、家长门户 | 学校和机构、客户管理、家庭客户管理；学生/升年进入家庭页签，门户进入通信页签；旧路径不失效 |
| 销售内混放合同、产品、财务 | 拆为销售拓展和合同与财务；业绩分配移为业绩页签，审批入口保留 |
| 通信/通知放总览，隐私请求放个人账户 | 统一客户服务分类；隐私请求是客户业务，不是个人账号设置 |
| 数据含学业升年 | 数据治理只含质量、导入、去重；提供能力过滤的页内导航；升年归家庭业务 |
| 分析与报告的多个入口 | 提供报告、消费分析、导出页签；保留角色可访问的侧栏入口，避免合并造成权限更窄的父页面屏蔽子功能 |
| 系统管理内另一个“仪表盘” | 改为系统管理概况；账户、安全、回收站、系统操作仍保留独立管理员权限 |
| 自动化、AI、增长 | 保留独立工作区：规则管理、建议审核、推广运营不是联系人档案标签页 |

## 实施细节

- 新迁移 083：客户创建 RPC、学校简称和原子编辑、跟进目标/记录、显式合同关联、RLS、幂等及多态主体硬删除清理。不运行现有生产/开发库迁移；部署本版本时必须应用迁移。
- 组织/个人新跟进同步写既有活动，统一历史视图纳入旧活动并避免镜像重复计数。目标日期按 UTC 统计；纯 NOTE 不计为有效联系。家庭关系水平显示可见家庭成员的最高联系人等级，不自动提升级别。
- 关联列表最多 50 条；历史列表最近 50 条；总记录数和目标计数使用数据库全量计数。学校里程碑采用既有非 REJECTED 证据口径；不能将目标设置等同于已达成关系。
- 家庭和个人的合同关联必须显式选择；负责人显示姓名，不直接显示 UUID。合同链接复用现有工作区，以合同编号搜索并校验后选中。
- 聚合 API 除主体 RLS 外，还按 contracts.view / opportunities.view 过滤业务数据，不能通过聚合面板绕开原业务页面的功能权限。
- 浏览器检查是实际组件、生产 CSS 与模拟 API 的 UI 测试；SQL 权限/事务另由真实隔离 PostgreSQL 18.4 验证，不把模拟 UI 测试称为完整线上端到端验证。

## 交付边界

轻量跟进目标不是完整企业 OKR 管理系统；建议为可解释规则，不自动推断私人家庭信息或强迫关系升级。第四级只记录自愿引荐。邮件模板必须经用户确认且遵守退订/同意/目的限制。外部邮箱收件同步、OAuth 生命周期、SMTP 凭据、服务商真实授权不在未提供账号时自动启用。
