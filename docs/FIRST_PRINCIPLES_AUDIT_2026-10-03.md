# 第一性原理审计：购买主体与服务交付

基线：v3.16.0 / d90c9c5。审计对象是代码及本地可验证应用，不代表已经检查或修改生产数据。

## 从业务结果反推模型

业务成功应由学生获得适合的升学路径、家庭作出知情选择、服务按约交付来衡量。学校和机构主要提供入口与合作关系；家庭是决策/购买群体；学生是服务受益人。组织关系熟悉程度、活动人数、转介关闭、申请提交、合同签署、确认收款分别是不同事实，不能互相替代。

上轮已实现结构化档案，但尚未形成完整业务路径。本轮重点检查“接触—需求—购买—交付”的连接点，而非增加孤立字段。

## 发现

|编号|优先级|设计问题与证据|修改方向|
|---|---|---|---|
|B01|P0|contracts / quotes 的 organization_id 必填；contracts API 只接受组织。真实家庭必须伪装成机构才能购买。|明确组织/家庭二选一的购买主体，复合外键隔离工作区；贯通报价、合同、续约、客户详情。|
|B02|P0|contract_summary 的 SECURITY DEFINER 聚合仅限制 workspace；合同列表按 RLS，汇总可能包含不可见合同。|汇总执行遵守调用者可见范围，加入角色回归测试。|
|B03|P1|收入与产品报表通过组织内连接及 count(distinct organization_id) 识别客户。|支持带类型的家庭购买主体，防止家庭收入漏算；保持币种、确认收款口径。|
|B04|P1|活动只有汇总人数，无法知道具体哪个家庭参与；转介关系不等于报名。|增加独立的家庭活动参与记录，明确意向/报名/到场/取消，保留人数未知语义。|
|B05|P1|升学路径只有阶段和 next_action，无法分配、跟踪逐项申请准备事项。|增加学生申请准备清单，记录事项、期限、状态和说明；完成清单不自动产生录取。|
|B06|P1|合同页面把所有合同金额称为年度金额，草稿和取消合同也显示续约提示；财务购买方选择仅组织。|修正合同状态提示与金额口径；购买方表单和搜索明确区分家庭与组织。|

## 本轮引入的新功能

家庭报价与直接签约、家庭活动参与登记、学生申请准备清单。这些能力不依赖假设佣金比例、统一录取标准或旅行审批制度，可作为真实业务操作的基础。

项目席位自动分配、佣金自动结算、大学录取预测没有足够业务规则支撑，本轮不把它们列入实施建议；不根据预算或亲密度推断录取概率。已有产品目录、任务、文件和审批继续承担各自职责，避免再建重复账本。历史 Markdown 保留，不自动猜测或批量回填身份及财务事实。
