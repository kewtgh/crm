# 产品保存与删除修补（2026-10-01）

发布版本：v3.10.1。

## 审计结论

- 产品目录从 PostgreSQL JSON 返回带时区偏移、可含微秒的 `updatedAt`；更新 API 原有 `z.iso.datetime()` 拒绝偏移格式，编辑提交可在数据库操作前失败。
- 产品页面和 API 原本未提供产品删除流程，仅有数据库删除策略。
- 新建、编辑、价格与生命周期流程使用笼统错误提示。保存与后续列表刷新处于同一失败分支，刷新失败会误报未保存，诱发重复提交。
- 本机开发应用和配置的 CRM 数据库未运行，不能据此确认生产服务器的部署版本。生产服务器目前为测试数据环境（用户说明）。

## 部署与验收

新迁移：`db/migrations/202610010081_product_save_and_recoverable_delete.sql`。使用项目标准部署流程；数据库迁移必须先于新版应用切换完成。手工更新开发环境时，先运行 `npm run db:migrate`，再构建并重启应用。

若只更新前端/API 而未执行迁移，删除 API 会提示产品服务不可用；必须补齐迁移，不能把该提示当成权限或重复代码问题。

可重复运行 `npm run test:products` 和 `npm run test:products:postgres`。后者只使用已有 `postgres:18.4-bookworm` 镜像并创建隔离数据库，限时 55 秒。服务器验收：编辑保存产品；管理员确认删除；目录不再显示该产品；超级管理员从回收站恢复。

未执行远端部署或完整浏览器矩阵。远端运行版本、迁移状态与浏览器端实际操作仍需在部署环境验收。
