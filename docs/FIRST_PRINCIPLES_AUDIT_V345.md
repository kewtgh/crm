# First principles audit for v3.45

Date: 2026-10-26. Baseline: v3.44.0 at `5cee02da03536039e422a4ffad728425ad7c8b20`, Node 24.22.1 LTS. An existing untracked V2 audit is outside this change. No production access or private operational evidence is used.

## Principles and coverage

CRM work succeeds when an authorized person can find the right record, understand whether the information is complete, and reach the intended context without accidentally initiating a business action. A missing search source is not proof that a record does not exist. A navigation click is a read intent, not an edit intent. Familiar keyboard and mobile interaction must preserve these meanings.

Reviewed the current release architecture and recent approval, communication, task, calendar, recycle, directory and deployment boundaries; traced global discovery through AppShell, related-search API/repository, navigation capabilities and target contract/product/finance pages. Existing versioned mutation receipts, consent, financial authority, RLS and V1 recovery remain their current owners. This is a new cross-module discovery pass, not a claim that all historical features or a production environment have been re-certified.

## Findings and adopted changes

| ID | Priority | Repository evidence and consequence | Adopted change |
| --- | --- | --- | --- |
| S1 | High | AppShell requests every related-record source, including USER which it immediately discards. Related search uses Promise.all, so one unavailable source suppresses every record source. | A bounded read-only global-search endpoint composes existing related queries for authorized record types, excludes USER, and returns per-source coverage with healthy results. Preserve the related-picker API's existing semantics. |
| S2 | High | Related results concatenate organizations and contacts before tasks, contracts and students; AppShell then slices the combined list to 12. Matching records in later types can disappear even though they were fetched. | Deterministic relevance within each type plus fair interleaving across types. Explicitly label bounded suggestions rather than claiming complete totals. Add record-type focus and page-command-only search. |
| S3 | High | The product route ignores focus, and the unused ProductsPage initialFocus opens an editor. Contract focus only selects a record already on the first page; its subsequent unfiltered read can lose that selection. Finance ignores quote in the search URL. | Read-only product detail focus; RLS-scoped contract ID filtering retained during reads; exact authorized quote focus with visible context and a way back to the normal list. Missing/inaccessible focus is explicit and does not reveal existence. |
| S4 | Medium | Search errors have no retry button; loading starts only after the debounce. Clear/Escape/outside paths duplicate state handling, and locale changes may retain record labels from the previous request. | A small shared search hook owns cancellation, context identity, immediate pending display, explicit retry and query/scope reset. Late responses cannot restore old results. |
| S5 | Medium | AppShell accepts an unvalidated result payload, hard-codes record destinations locally, and does not guard Enter during IME composition. Search results can grow beyond the visible panel. | Shared query/result/destination contracts, strict query/type validation and internal UUID-based links; IME-safe keyboard handling, active-result scrolling, valid combobox/listbox structure and bounded responsive panels. |
| S6 | Medium | Users cannot tell a genuine empty result from incomplete coverage, or narrow the cross-module fan-out to one relevant type. | Bilingual coverage feedback, source-specific failure labels and explicit retry, type scope and pages-only mode. Search terms/results stay in page memory; no browser storage or additional persistent search index. |
| S7 | High | User reports failed schedule creation and duplicate date/time selectors. The RPC gateway passes JavaScript arrays directly to node-postgres, which encodes PostgreSQL arrays even when the function argument expects JSONB; appointment attendees are JSONB while reminders are integer[]. DateInput combines native controls with a second custom picker. | Reproduce transport behavior and actual appointment creation on a fresh isolated PostgreSQL instance; serialize array arguments according to current function metadata while preserving native SQL arrays, defaults and existing authorization. Use one integrated text field with a native picker, support compact entry, improve bounded calendar validation/consent/relation error guidance, and preserve exact-request recovery. |

All S1-S7 changes and the included features are adopted for this release. The calendar transport and shared-control work was added from the user's explicit report during this audit. No new production infrastructure, database, migration, background job, customer outreach, automatic business retry or paid service is required. Wider indexing, saved customer searches and bulk business actions are not proposed by this audit.

The shared input inventory found 63 DateInput call sites across 35 components (some render multiple dynamic fields). All are covered by the same single integrated control: one text field with one native-picker button inside its border, rather than adjacent native/custom selectors. Compact HHmm and MMDD entry is global; MMDD uses the current year in the account timezone (device year for standalone forms), not the currently viewed calendar year. Invalid dates, leap days and ranges remain invalid. This also covers consent quiet times, tasks, contracts, finance, admission milestones, enrollments and support editors. The auxiliary picker has no form owner or submitted name; it cannot introduce a second validation/submission value. Uncontrolled fields restore their defaults on form reset; parent-controlled fields retain their owner's state.

## Architectural decisions

Keep relation pickers and global discovery as separate read contracts while reusing existing RLS-backed repository queries. Global results expose only IDs, type and display labels; source failures expose fixed type/status metadata, not raw database errors. Keep capability checks on the server even when the same types are hidden by the client. Derive destinations from validated type/UUID instead of trusting arbitrary response URLs. Deep-link fixes use current read models and existing business controls.

The transport cause also matches the documented distinction between arrays and objects in [node-postgres parameter conversion](https://node-postgres.com/features/queries); the disposable PostgreSQL experiment independently reproduced it with this repository's actual appointment function.

Findings above are from repository code; target-environment and production behavior are not inferred from these documents.
