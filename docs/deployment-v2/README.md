# Lumina CRM Deployment V2：离线开发与隔离生产设计

日期：2026-10-25。设计版本：0.1。仓库审计基线：`926819e566c5736e83817cd55e45dbf3e5337e66`，CRM `3.44.0`。

本目录是第一阶段交付：现有系统审计、架构决策、协议和后续实施计划。它没有安装 V2、修改 V1 执行路径或证明生产环境已经兼容。文中的 V2 路径、命令、字段和服务名均为待实现的接口约定，不能作为当前生产操作命令。

## 结论

日常发布的最小职责是：验证一个已构建的发布制品，在已配置好的隔离环境中推进一次有证据的状态转换，再确认实际运行版本。源码更新、生产构建、部署器升级、基础设施维护和历史故障归档应退出这条路径。

V1 已有重要安全保障，包括项目隔离、进程锁、迁移校验、兼容性回退约束、内部与公网健康分离、原子文件写入。主要问题是这些保障依赖应用源码中的执行器，并通过多个文件、安装组件和跨版本协议共同解释部署结果。继续叠加兼容分支无法消除这个依赖方向。

V2 采用以下设计基线：

1. 独立版本的 Deployment Agent，包含私有运行时；应用发布制品不能修改或升级 Agent。
2. CI 构建应用镜像和签名发布描述，生产按摘要导入或拉取；日常发布不执行 Git、npm、Buildx 或系统安装。
3. 一个本地事务状态库保存部署请求、步骤证据、接受版本和归档事实；JSON 报告是派生输出。
4. 一个项目写锁约束执行、恢复和升级；结果不明的外部副作用必须先核实，不根据日志缺失、时间或进程退出推断安全重放。
5. 精简 Preflight 只检查本次操作的必要条件，逐项区分失败、未知和因依赖未执行。
6. 先在真实启动的 Ubuntu 26.04 VM 验证 Rootless Docker、systemd、cgroup v2 和崩溃恢复，再由管理员决定生产试点。

## 边界与责任

| 责任方 | 可以执行 | 不属于本阶段授权 |
| --- | --- | --- |
| 开发环境 / Codex | 仓库只读审计、保存设计；后续独立里程碑中开发与本地验证 | 连接生产、运行生产 SSH / Docker / systemd / 数据库命令 |
| 独立 CI / 测试 VM | 使用虚构数据构建、部署、迁移、崩溃注入和重启 | 生产凭据、生产网络访问、生产数据副本 |
| 管理员 | 后续审阅具体制品、诊断输出和操作计划，手动执行批准的生产操作 | 被普通应用发布隐式触发的系统安装、Agent 更新或共享服务变更 |

不改变既有生产 Docker、PostgreSQL、systemd 或其他项目。V2 试点需要的新文件和项目专属服务必须在后续独立维护窗口中逐项审阅；它们不是本设计的自动执行步骤。现有业务迁移属于发布副作用，必须显式列入管理员批准的计划；更换 PostgreSQL、数据库角色初始化和备份恢复不属于日常发布。

公开仓库只保存架构、代码引用、虚构示例和最小化验收结论。管理员诊断包、原始执行证据和任何真实环境材料留在管理员受控存储或 Git 忽略的 `work/`，不直接提交。

## 简化准则

每个阻断条件必须说明它防止哪一种本次操作风险。只影响生产构建的 Buildx / BuildKit 条件不能阻断镜像发布；历史归档不能成为永久的应用运行依赖；推荐版本不能伪装成必需版本。

第一版不引入远程控制平台、管理网页、多主机调度、自动基础设施修复、自动反向迁移或自动 Agent 更新。保留单主机、单项目、单写者模型。新增能力限于可信制品、准确诊断、可核实恢复和真实环境验证。
