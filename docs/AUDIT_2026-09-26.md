## 架构评估及本轮选择

- 应用已有 API capability、来源/CSRF 检查、用户上下文事务、RLS、后台队列及受控部署。抽查中未获得需要推倒重建这些边界的证据。
- 重复的前端状态和原生/异步生命周期处理比缺少业务模块更直接影响可用性。本轮在现有边界内修复，并补真实函数行为测试，减少仅靠正则源码契约遗漏错误的风险。
- 新功能选择：独立未读通知中心、任务关注筛选、带行号的导入预检反馈。这些直接复用现有数据和权限，不引入新的外部服务或商业假设。
- 大型 AI 自动决策、短信供应商、跨组织共享等缺少业务规则和服务配置，不列为本轮建议或实施承诺。
