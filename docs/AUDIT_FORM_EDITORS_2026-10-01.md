# v3.11.0 编辑体验审计与修改计划

范围：用户要求的编辑弹窗、金额/币种、结构化字段、日期选择和双语名称规则。保留现有权限、并发保护、时区转换、API 和数据兼容性，不扩大到全项目发布审计。

## 审计发现

1. 共享编辑器采用固定右侧抽屉，桌面编辑区域过窄；员工/团队独立弹窗也需要统一宽度。
2. 财务通用 Field 没有金额格式化，且折扣 0 被错误的最小金额 0.01 拦截；币种文本框没有规范选择。
3. 应收分期要求手写 `日期:金额;...`，难以验证并容易出错。
4. 标签、兴趣、课程分类依赖逗号文本；学年、年级、语言、来源等缺少结构化选择。
5. 日期虽然部分已使用原生 date/datetime-local，但入口不够明确；通用 Field 和分期仍需要统一日历/时间选择入口。
6. 中英文名称各自 required，API 也各自必须填写；仅改界面会继续出现保存失败。部分数据库函数还有旧的长度校验。
7. CRM 和教育编辑的版本字段不接受数据库返回的带偏移 ISO 时间，可能导致正确编辑仍无法保存。
8. 必填状态缺少一致的可见标记；关联记录选择、组合条件和动态导入修补表单尤其容易遗漏。导入修补行仍将两个名称分别必填，并用文本框处理日期、金额和枚举。
9. 发布版本散落于清单、锁文件、应用常量和文档；缺少安装前的一致性检查。旧回归断言依赖分期文本框占位符，界面更新后会产生过时的 CI 失败。

## 执行计划

- [x] 共享编辑器居中，扩大桌面宽度至 960px，保持移动端适配、内部滚动、键盘焦点和取消/提交行为；员工/团队独立编辑窗口同步加宽。
- [x] 共享 MoneyInput/CurrencySelect：展示千位分隔，提交原始数值，限制精度/范围；金额页面接入，保留受控输入和重置行为。
- [x] DateInput 提供显式日历/时间按钮；学年/成立年份用选择控件；已有时区转换不变。
- [x] 标签/兴趣/课程分类使用可增删标签，语言/年级/渠道/来源提供候选并兼容历史自定义值；未点击添加的标签草稿仍随表单提交。
- [x] 分期改为可添加/删除的日期与金额行，提交结构化数组，保留至少一期、最多 24 期；折扣支持 0。
- [x] 双语名称前端组合校验、后端组合校验，至少一项非空；另一项使用显示回退，不翻译或截断。部分更新不覆盖未提供的名称。商机标题采用同样的组合规则。
- [x] 补齐必要数据库兼容迁移和带偏移的编辑版本校验；不重写历史迁移。
- [x] 原生必填字段、关联记录选择和组合必填条件显示红色标记/说明。导入映射允许任一语言名称；动态修补行接入统一控件，非法原始日期保留至用户明确选择或清空。
- [x] 添加版本/锁文件一致性检查 `npm run release:check`，接入 CI 安装前检查，登记新回归测试并更新过时的分期断言；保留依赖审计和原有 lint 规则。
- [x] 添加针对性回归测试，依次执行类型检查、相关 lint、相关单测、生产构建及 Chromium 1243 编辑控件验证。只有影响构建的源码修正后才重新构建。
- [x] 更新为 3.11.0，保存审计、计划及验证结果；提交记录以 Git 日志为准。本次不运行完整十阶段浏览器矩阵或完整数据库回归。

## 建议与边界

引入的新能力为统一格式化金额、显式日历选择、标签编辑器和可视化分期编辑；不新增外部日期组件依赖。开放词汇用 datalist 保留自定义值，枚举/币种/学年用结构化选择。富文本、业务说明、自由备注和代码/编号不应强制枚举化。
