## 1. 结论

v3.4.0 工作树干净，`main` 比 `origin/main` 领先 1 个既有提交。认证、Origin/CSRF、
SCIM Bearer、Webhook 签名、PostgreSQL/RLS、迁移校验、后台投递 timeout/幂等与分页基础
保持成立。本轮静态检查没有发现 P0、认证绕过、危险 HTML 注入、`eval`、真实秘密入库、
TODO/FIXME 式生产占位或已知 npm 漏洞。

本轮最高价值缺口是组织业务日没有成为一等架构概念。22 个当前生效的 PostgreSQL 业务函数
依赖 `current_date`，Node 合同剩余天数又使用 Web 进程本地午夜，而界面显示使用个人时区。
在 UTC 日期边界附近，同一个合同、报价、应收、同意、销售报表、数据质量或学年推进动作可能
得到互相矛盾的“今天”。v3.4.0 已把它记录为架构门禁，但仓库已有 5 个受支持 IANA 时区，
可以通过 workspace 配置和事务级数据库时区一次性关闭，不需要逐函数复制业务规则。

第二个系统性缺口是共用 `AccessibleDrawer` 没有异步提交关闭保护。员工创建页曾单独修复，
但合同、日历、沟通、自动化、客户 360、线索、AI 审核、导出等写流程仍可在请求结果不确定时
用 Escape、遮罩、关闭或取消按钮退出。任务优先队列还静默只渲染前 12 条，且几个较旧页面
绕过统一的用户时区格式器。

## 3. 审计发现

### P1-ARCH-01：组织业务日依赖数据库/Web 服务器时区

`contract_summary`、`consumption_report`、`sales_performance_report_v220`、报价接受、应收刷新、
营销同意、数据质量和学年推进等 22 个当前函数使用 `current_date`。应用数据库事务只设置
用户、workspace、角色和 AAL，没有设置 PostgreSQL `TimeZone`；Worker 数据库访问也没有
workspace 时区上下文。数据库主机时区或容器默认值因此会直接改变业务结果。

`lib/contract-repository.ts` 还用 Node 本地午夜计算剩余天数，在数据库与 Web 进程时区不同
时会与 SQL 摘要不一致。局部替换某一个函数会继续留下跨模块矛盾。

### P1-UX-02：共用写抽屉允许不确定提交期间关闭

`AccessibleDrawer` 无 pending/close-disabled 合同，Escape、遮罩和标题关闭按钮总是执行
`onClose`。多个调用方的取消按钮也保持可用。请求不会随抽屉卸载而取消；稍后成功或失败时，
用户可能看不到结果，随后重复提交。

应在共用组件层阻止 Escape/遮罩/关闭，并让调用方在 mutation pending 时同步禁用取消。
关闭保护还必须有可访问的 `aria-busy` 状态，不能只做视觉禁用。

### P2-DATA-03：任务优先队列静默截断为 12 条

任务 workspace 摘要基于完整 `items`，但优先队列只渲染 `slice(0,12)`，没有“显示 12/总数”
提示或跳转到完整任务表。超过 12 条时，用户会看到完整统计数字却无法理解队列为何缺项。

### P2-UX-04：部分时间显示绕过个人时区与语言

沟通消息、自动化运行、门户访问和回收站时间直接调用 `toLocaleString()`，其中部分连 locale
也未传入；它们没有使用 `UserPreferencesProvider` 的个人时区和日期格式。财务分期输入还用
硬编码 `2026` 示例，时间推移后会显得低级并误导输入。

### P3-MAINT-05：业务时区没有集中、可验证的上下文原语

若逐个改写 22 个 SQL 函数，未来新函数仍可能回退到服务器日期。应让 workspace 时区成为
数据库事务上下文的一部分，并给 Worker 提供显式 workspace 事务原语；管理写入应校验有限
时区集合并产生审计事件。

## 4. 纳入本轮的修复与产品增强

1. **组织业务时区设置**：新增管理员页面，展示并修改 workspace 业务时区，说明它与个人
   显示时区的区别，并显示当前组织业务日预览。
2. **事务级业务日一致性**：用户数据库事务和带 workspace 的 Worker 事务设置本地
   PostgreSQL `TimeZone`；合同剩余天数改用同一业务日。
3. **可靠异步抽屉**：共用抽屉支持 pending 关闭保护，所有直接相关写流程接入并补充
   `aria-busy`/禁用取消行为。
4. **任务队列完整性**：明确显示“前 12/总数”并提供跳到完整任务表的入口。
5. **时间格式统一**：旧页面接入个人时区格式器；移除会过期的硬编码日期示例。
6. **可验证发布**：新增 v3.5 行为契约、迁移、资料、定向浏览器证据与版本更新。
7. **可切换验证码提供方**：用户补充要求大陆网络可关闭 Turnstile；关闭时强制使用现有
   自托管 ALTCHA，而不是取消验证码，并由管理员 AAL2 写入审计。

### 补充审计：Turnstile 大陆可用性与 ALTCHA 执行边界

初始审计完成后，用户补充了 Cloudflare One 邮箱/访问保护与大陆网络使用场景。现有代码有
Turnstile 故障回退，但没有持久化管理员开关；客户端也始终先挂载 Cloudflare 脚本。进一步
交互验证还发现 ALTCHA 的 blob Web Worker 被 CSP 拦截，因此“关闭 Turnstile”若只改 UI
会得到无法完成的本地验证码。

本轮将此作为 P1 安全/可用性问题关闭：workspace 策略默认开启 Turnstile，管理员+AAL2 才
能改变；服务端拒绝策略关闭后的旧 Turnstile token；登录、SSO 与找回密码直接使用 ALTCHA；
CSP 仅为 Worker 增加 `'self' blob:`；Cloudflare One 明确作为独立身份/访问层，不替代
CAPTCHA、限流、MFA 或可信设备。

## 5. 边界

本轮实现 workspace 业务时区能力并默认迁移为 `Asia/Taipei`；管理员可以在 5 个已验证时区
中修改。它不会把个人显示时区当作组织规则，也不会允许未经时区转换测试的任意 IANA 值。

真实 VPS 的系统时区、PostgreSQL 连接容量、Caddy/DNS/TLS、真实邮件/IdP/SCIM、独立备份
生命周期和代表性容量/P95 仍是外部生产门禁。仓库修改不会声称已改变这些外部系统。
