## CI publication contract

The full release gate still runs its required checks and preserves failure outcomes. Configure,
release and cleanup command details are retained privately under ignored work/ci-private/. Public
logs contain safe status/heartbeat messages; runner home/work/cache/temp paths are masked before
subsequent steps. Private raw evidence is capped locally and never uploaded.

Only work/public-artifacts/browser-qa-summary.json is published. The projection accepts a fixed
schema: revision/version, typed result states and numeric counts. It excludes arbitrary fields,
URLs, paths, messages, screenshots, traces, env and source data. Freshness and current workflow run/
attempt are checked. Missing, malformed or stale input reports UNAVAILABLE/NOT_RUN rather than PASS.
An unsuccessful publisher cannot trigger the upload step; failure diagnostic artifacts are not
broadly copied. **Screenshot publication is disabled**, including synthetic QA screenshots.

A lightweight public-privacy workflow runs on pushes and pull requests, including documentation-only
changes excluded by the larger CI workflow. All workflow definitions and invoked publication helpers
were checked for broad artifact uploads, environment dumps and deliberate secret echoes. No Production
secrets are required by these privacy checks.

The earlier read-only remote inspection found zero listed releases/assets and zero listed Actions
artifacts, and inspected one successful CI log plus bounded issue/PR metadata. This does not establish
that old artifacts/logs never contained private information. The patched workflows have been verified
locally with synthetic success/failure fixtures; a new remote full release run is not claimed here.

The ignored plan enumerates 92 originally affected historical blobs, refs, commits, paths and replacement
rules. The owner approved main-only rewrite/publication and noreply replacement for the owner's metadata.
The rewrite preserves the authorized legal body and removes known identifying company,
bank, people, counterparties, transaction provenance and personal paths. Current sanitized historical
master blobs should retain their bytes. Any newly discovered private binary requires a safely replaced

content-addressed inventory and changed bytes rescanned. The two DOCX masters and final application
tree remained byte-identical to the reviewed patch. SCIM resource routes and generic container
home paths were explicitly classified as public-safe, rather than deleting their history findings.
Collaborator/fork coordination and review of historical CI outputs remain necessary. Future public
Git identity is recommended: FUTURE_PUBLIC_GIT_IDENTITY_RECOMMENDED. Owner metadata approval is
recorded; no global Git setting is changed. If an active credential is found later,
revoke/rotate and verify invalidation before history cleanup, with separate authorization.

**Not performed:** BFG, remote branch/tag deletion, credential rotation, historical Actions removal
or Production access/deployment. Only the explicitly authorized main rewrite is published; private
backups are not pushed. The owner separately approved retargeting the local legacy fix branch to its
corresponding sanitized commit; that branch is not published. Force push cannot recall old logs,
downloaded clones, fork refs, unreachable hosting objects or external caches.
